[워크플로우](./workflow.mdx) 가이드는 draft PR 에서 끝나요. 이 가이드는 그 뒤를 다뤄요. 끝난 작업의 기록이 어디로 가고, 다음 작업에 어떻게 돌아오는지요.

## 동작 원리

### 한 바퀴

<KnowledgeLoopDiagram />

왼쪽 줄은 작업 하나가 지나는 길이고, 오른쪽 줄은 한 주 단위로 도는 길이에요. 기록을 사람이 따로 정리하지 않아요. 플랜 파일이 작업 중에 쌓이고, 정해진 시각에 레인이 그 파일을 읽어요.

### 플랜 파일이 원재료예요

<PlanAnatomyDiagram />

플랜은 무엇을 하려는지를 적고, Outcome 은 실제로 일어난 일을 적어요. 리뷰에서 떨어진 횟수, 고친 횟수, 들어간 커밋이 Outcome 에 남아요. 월요일 compound 는 fix 루프가 두 번 이상 돈 기록을 피할 수 있었던 실수의 신호로 읽어요.

증류는 플랜 말고도 버그 조사 리포트와 세션을 마칠 때 남긴 노트를 같이 모아요.

### 금요일에 레인이 돌아요

<FridayLanesDiagram />

레인은 macOS launchd 가 정해진 시각에 돌려요. 제가 기억하지 않아도 돼요.

- **증류** — 플랜 증류는 기록을 결정 노트로 옮기고, 비슷한 노트가 셋 이상 모이면 그 공통점을 개념 노트로 써요. 레인 끝에서 지식베이스 개요 한 장을 다시 써요.
- **제안** — compound 와 마찰 리포트는 제안일 뿐이라 검색 대상 밖에서 만들어져요. 기계 검사와 작은 모델의 심사를 둘 다 통과한 것만 검색 대상으로 올라가요. 검증되지 않은 제안이 지식처럼 검색되지 않게 하려는 거예요. compound 가 제안한 규칙 수정을 실제로 적용할지는 제가 정해요.
- **팀 wiki** — 회고 레인이 팀 wiki 로 올릴 만한 문서 후보를 골라 두고, 올릴지는 제가 정해요.

### 다음 플랜이 인용해요

플랜을 쓰기 전에 같은 주제의 지난 결정을 지식베이스에서 찾아요. 찾은 결정은 다시 정하지 않고 인용하고, 예전에 버린 대안은 다시 제안하지 않아요. 지난 결정은 가설로 다뤄서, 그 결정의 전제가 지금도 맞는지를 구현 체크리스트 첫 줄에서 확인해요.

## 내 설정

### 증류된 결정 노트 한 장

[aicommit2](https://github.com/tak-bro/aicommit2) 에서 커밋 메시지 생성 중 진행률을 보여 주는 작업을 하고, 그 플랜이 금요일에 증류된 노트예요. 원본 플랜 경로와 커밋이 붙어 있어서 노트에서 원재료로 거슬러 갈 수 있어요. 표에서 "기각" 줄이 다음 플랜이 다시 제안하지 않는 대안이에요. 구현 결정은 하나만 남기고 줄였어요.

# 진행률 단위 = settled Request — 메시지 축·토큰 축 기각

Issue #258("커밋 생성 중 로딩 슬라이더") 대응. 근본 원인은 피드백 부재가 아니라
**거짓 피드백** — 응답 도착 전에 empty-state 문구 `⚠ No commit messages were
generated`가 렌더되어, 아직 작업 중인데 이미 실패했다고 선언.

## 결정

| 선택지 | 결정 | 근거 |
|---|---|---|
| 진행률 단위 | **settled Request** = (provider, model) 쌍 | 분모 Σ models가 시작 전 확정. 성공·실패 모두 카운트 → 분모 항상 도달 |
| Message 단위 | 기각 | `generate`(1-5/model) 탓에 실패 1건이면 분모 미도달 — `4/6`에서 멈춘 카운터는 #258을 픽스 안에서 재현 |
| 토큰 축 %/슬라이더 | 기각 | 분모가 존재하지 않음 (ADR-0001) |
| dead-air 갭 픽스 | 기각 | 실측 ~50ms — 지각 불가. 초안의 MUST 항목이 측정으로 사망 |
| 카운터 문구 | 단위 명사 생략 `(2/3)` | `generated`/`responded` 둘 다 실패를 세는 순간 거짓말이 됨 |

## 구현 결정

- **finalize 위치 = model 레벨**: provider 레벨 래핑은 `model: [a, b]` provider에서
  1회만 발화 → `1/2` 스톨. 단일 model provider들로는 두 레벨이 일치해 이 결함이
  안 보임 (검증 V5의 존재 이유).
