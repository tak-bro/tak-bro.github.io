코딩 에이전트에게 일을 맡길 때 매번 같은 길로 보낸다. 작업 크기가 어떤 단계를 거칠지 고르고, 플랜 파일이 할 일과 검증 기준을 들고, 슬라이스마다 리뷰 게이트를 지나고, draft PR 에서 멈춘다. 머지는 내가 한다. 단계 하나하나는 [에이전트 설정](./agent-config.mdx) 레포의 스킬(슬래시 명령)이다. 그 레포는 비공개라서 그대로 쓸 수는 없고, 크기 표와 리뷰 루프 규칙은 원문을 아래에 실었다.

## 동작 원리

### 크기가 단계를 고른다

모든 작업에 전체 단계를 돌리지 않는다. 바뀌는 파일 수로 크기를 정하고, 크기마다 거칠 단계가 정해져 있다.

| 크기 | 기준 | 단계 |
|---|---|---|
| S | 파일 1~2개 | 구현 → 리뷰 → ship (버그면 원인 조사부터) |
| M | 파일 3~10개 | 탐색 → 플랜 → 슬라이스 루프 → ship |
| L | 파일 10개 이상 | M 앞에 스코프 리뷰, 뒤에 구조 개선이 붙는다 |
| XL | 무엇을 정해야 할지부터 모름 | 질문으로 결정을 먼저 푼 뒤 플랜 → L 과 같다 |

파일 수가 적어도 인증, 인가, 사용자 입력, DB 쿼리, 파일 경로, 외부 API, 암호, 시크릿, 공개 API·계약을 건드리면 최소 M 이다.

`/orch` 를 쓰면 이 선택을 에이전트가 한다. 첫 줄에 작업 종류(추가·변경·버그·구조 정리), 크기, 완료 기준과 그것을 재는 명령을 한 줄로 선언하고 그 단계들을 끝까지 잇는다. 선언이 틀렸으면 그 줄을 보고 내가 고친다.

### 플랜은 파일이다

M 이상은 플랜을 레포의 `.claude/<날짜>/PLAN-<시각>.md` 에 쓴다. 이 파일이 작업의 상태 전부다. 세션이 끊기거나 컨텍스트가 압축돼도 파일을 다시 읽고 이어 간다.

- **슬라이스 큐** — 할 일을 수직 슬라이스로 나눈 표다. 슬라이스 하나는 한 층의 조각이 아니라 끝에서 끝까지 동작하는 좁은 경로이고, 혼자 확인할 수 있다. 체크박스가 진행 상태다.
- **검증 계약** — 완료 기준을 한 줄씩 적고 각 줄에 그것을 재는 명령을 묶는다. 구현 전에 이 명령들이 실제로 실패하는지 먼저 돌려 본다. 처음부터 통과하는 검사는 아무것도 재지 않는 검사이기 때문이다. 구현이 시작되면 계약을 해시로 고정한다. 구현하는 모델은 통과 여부 칸만 채우고, 그 기록은 슬라이스 리뷰와 ship 직전에 스크립트가 다시 대조한다.

### 슬라이스마다 리뷰 게이트를 지난다

슬라이스 하나를 구현하고 검증 명령이 통과하면, 같은 턴에 리뷰어 서브에이전트를 띄운다(문서·설정만 바뀐 슬라이스는 메인 세션이 diff 를 직접 본다). 리뷰어는 메인 세션의 대화를 모른 채 플랜과 diff 만 보고 발견 사항을 돌려준다. Critical 이나 Important 가 있으면 고치고, 검증을 다시 돌리고, 같은 리뷰어에게 다시 보낸다. 이 루프는 슬라이스마다 최대 3회다. 같은 문제가 두 번 연달아 다시 나오거나 3회를 다 쓰면 멈추고 나에게 보고한다.

게이트를 통과하면 슬라이스를 커밋하고 큐에 체크를 한 뒤 다음 슬라이스로 넘어간다. 슬라이스 사이에 나에게 묻지 않는다.

### 마무리는 draft PR 에서 멈춘다

`/orch` 로 돌리면 큐가 빈 뒤 브랜치 전체를 한 번 더 리뷰한다. 슬라이스 게이트는 슬라이스 하나씩만 보므로, 슬라이스를 가로지르는 문제는 여기서 잡는다. 그다음 `/ship` 이 마무리 게이트를 돈다. 화면을 그리는 코드가 바뀌었으면 화면 QA(웹은 브라우저)를 돌리고, 로직이 바뀌었는데 테스트가 하나도 안 바뀌었으면 빠진 테스트를 쓰게 한다. 그 뒤 커밋을 push 하고 draft PR 을 연다.

머지는 내가 `/land` 로 부른다. `/land` 가 draft 면 ready 로 바꾸고, squash 머지(개인 레포), 쌓인 PR 의 base 옮기기, worktree 정리를 한 번에 한다.

### 계약 한 줄의 모양

```text
- AC-1 · s01 · WHEN `pnpm build` 가 끝나면 THE <파일> SHALL <기대 결과> · check: s01-ac1 · status: FAIL · evidence: —
```

`check:` 는 플랜의 검증 명령 절에 있는 명령 이름이다. `status`·`evidence` 두 칸만 구현 중에 바뀐다. evidence 에는 실제로 돌린 명령과 판정을 떠받치는 출력 한 줄을 적는다.

## 확인

아래 두 스크립트는 에이전트 설정 레포의 `claude/hooks/` 에 있어 그 레포를 연결한 맥에서만 돈다.

1. 플랜의 검증 명령을 전부 돌린다. 모두 green 이어야 한다.

```sh
bash ~/.claude/hooks/verify-check.sh --plan .claude/<날짜>/PLAN-<시각>.md --all   # verify-check: N/N green
```

2. 계약의 PASS 기록이 실제 실행 기록과 맞는지 대조한다.

```sh
python3 ~/.claude/hooks/ac-contract.py audit .claude/<날짜>/PLAN-<시각>.md   # audit: ok
```

3. PR 이 draft 로 열려 있는지 본다. 머지는 아직 안 된 상태여야 한다.

```sh
gh pr view --json isDraft,state   # {"isDraft":true,"state":"OPEN"}
```
